An outside pass over the open questions in [BLOCKED.md](BLOCKED.md),
[SEARCH-ROUTES.md](SEARCH-ROUTES.md), [SUGGESTIONS.md](SUGGESTIONS.md) and
[EXPOSURE.md](EXPOSURE.md).

**Everything with a number in it was measured here, today**, by calling the

## F-1 · A free, keyless cross-service resolver exists — `BLOCKED.md` is wrong

`BLOCKED.md` ends its cross-service discovery entry with **"No free
cross-service resolver exists. This is now a settled finding rather than a
regression to watch."** That is the one claim in the file that did not hold.

**MetaBrainz runs one.** The ListenBrainz *dataset hoster* at
`labs.api.listenbrainz.org` publishes six endpoints that were never checked:

```
/spotify-id-from-mbid/json?recording_mbid=…        /spotify-id-from-metadata/json
/soundcloud-id-from-mbid/json?recording_mbid=…     /soundcloud-id-from-metadata/json
/apple-music-id-from-mbid/json?recording_mbid=…    /apple-music-id-from-metadata/json
```

Measured:

```
GET /spotify-id-from-mbid/json?recording_mbid=42683722-d790-43df-8478-627d90be1c80
  200 · Access-Control-Allow-Origin: *
       Access-Control-Allow-Methods: HEAD, GET, OPTIONS, POST
  [{"recording_mbid":"42683722-…","artist_name":"Flume feat. kai",
    "release_name":"Skin","track_name":"Never Be Like You",
    "spotify_track_ids":["7hZhKh0NmmlUfoQkUkCflm"]}]
```

**GET, no key, no account, `ACAO: *`** — so like Audius and iTunes it can be
called from the visitor's browser on the visitor's IP, never from Timbre's
shared egress.

### The whole chain, measured over 15 songs

Every hop is keyless. Deezer is already a registered provider, so hop 1 costs
nothing new.

```
Deezer /search → /track/{id}.isrc          15/15
MusicBrainz /ws/2/isrc/{isrc} → mbid       13/15
ListenBrainz → Spotify track id            10/15
ListenBrainz → Apple Music track id         9/15
ListenBrainz → SoundCloud track id          0/15
```

**The 10 Spotify ids were then verified against the embed page: 10/10 rendered
the correct track**, matched on title and artist. This is the id `BLOCKED.md`
calls "no longer obtainable for free" and that `SEARCH-ROUTES.md` Part 2 gives
as the reason Spotify search did not ship. **It is obtainable, for free, without
a developer app, from a browser.**

The two MusicBrainz misses were *Blinding Lights* (`USUG11904206`) and Four
Tet's *Baby* (`GBXNG2051002`) — the ISRC simply is not in the database. That is
the weakest hop and the one to instrument.

### It is variant-aware, which matters more than the hit rate

Asked for the **instrumental** of *Never Be Like You*
(`244cb0ea-ed40-4a6f-a846-9ceec536b696`) it returns `"spotify_track_ids": []` —
it does not fall back to the parent recording. Contrast MusicBrainz *search*,
which `BLOCKED.md` records as ranking that same instrumental at 100 against 92
for the real thing. **Going in by ISRC and out by MBID skips the ranking problem
entirely**, because neither hop is a fuzzy match.

Two variant caveats did survive to the Spotify side and should be expected:
`Wonderwall` resolved to *Wonderwall - Remastered* and Peggy Gou to *(It Goes
Like) Nanana - Edit*. The first is noise by the README's own rule; the second is
a variant and would have to agree.

### What it does not do

- **SoundCloud: 0/15.** The endpoint exists and answers `200`; the index is
  empty for this material. SoundCloud stays blocked, and F-4 is its answer.
- **One MBID per GET.** Comma-separating fails UUID validation. `ACAO` advertises
  `POST` and the sibling endpoints take JSON arrays, so batching is very likely
  available — **not verified here, no POST was sent.** That belongs in
  `SUGGESTIONS.md` until someone runs it.
- **The labs host is not SLA'd, and this was seen live.** Two neighbouring
  ListenBrainz APIs answered `500` during this session:
  `/1/explore/lb-radio` → *"LB Radio currently disabled due to high load"*, and
  `/1/popularity/top-recordings-for-artist` → the same. The id endpoints and
  `similar-recordings` were re-sampled and were byte-stable, but **treat this
  service as best-effort and make every call abstain-on-failure**, the way the
  ranker already treats an absent list.

The provenance is the good news, and it fits the pattern `SUGGESTIONS.md` S-9
identifies. This is not a company's free tier. It is a non-profit's dataset,
built so ListenBrainz can export its own playlists to Spotify — the reason it
exists is structural, like MusicBrainz's UA policy and the Internet Archive's
mission, not generous, like Odesli's and the FMA's were.

**Where this goes:** it rewrites the cross-service entry in `BLOCKED.md`, and it
demotes the Spotify entry from `DEFERRED`-on-the-id to *deferred on §IV.2 only* —
a much narrower and more honest blocker.

## F-2 · `youtubei.js` deletes the Python sidecar, and is 6× faster cold

`DEPLOY.md` (unstaged) records ytmusicapi's warm-up as **3.1–3.4 s on the first
search of every client instance, ~0.9 s warm**, and calls it a real number to
hold against the container option. The same work in Node:

```
youtubei.js 18.0.0, Node, retrieve_player: false
  Innertube.create()            1610 ms   (once per process)
  first  music.search()          563 ms
  second music.search()          537 ms
```

**563 ms against 3 100–3 400 ms cold; 537 ms against ~900 ms warm.** And the
`create()` cost is per *process*, not per client — the thing `app/client.py`'s
`_clients` cache exists to amortise.

### Every list the product depends on is there

```
music.search('…', {type:'song'})    →  parsed songs, ids, durations, albums
music.getUpNext(videoId)            →  50 items   (= get_watch_playlist)   1421 ms
music.getRelated(videoId)           →  6 sections, "You might also like" ×20  985 ms
```

Those are exactly `ytmusic:radio` and `ytmusic:related` from
`RECOMMENDATIONS.md`.

### `musicVideoType` survives, which is what B-2 and B-3 hang on

The parsed helper does not surface it, but the raw client does:

```js
const raw = await yt.actions.execute('/search',
  { query: 'Blinding Lights', client: 'YTMUSIC', parse: false });
// MUSIC_VIDEO_TYPE_ATV ×15 · OMV ×14 · UGC ×9 · PODCAST_EPISODE ×3
```

So the `OMV(0) → UGC(1) → unknown(2) → ATV(3)` rank from `BUGS.md` B-3, and the
always-also-search-`videos` fix from B-2, both port directly. **Note the
`PODCAST_EPISODE` tier**, which the Python path's four-way rank has no branch
for.

### What this actually removes

Not just latency — a whole deployment target and most of Part 4 of `EXPOSURE.md`:

- the second Vercel project, and `DEPLOY.md`'s two-project dance
- `YTMUSIC_SHARED_SECRET`, and with it **E-11** (no rotation path) and **E-12**
  (the secret is the sidecar's only defence)
- `uv`, `uv.lock`, the `--locked` CI step, the Python 3.11 prerequisite
- the two-terminal dev setup, and `RUNNING.md`'s "the most common symptom by far
  — search returning nothing — is just the sidecar not running"
- `/api/health` returning 503 for a service that no longer exists

### And it does not walk into the 2026 YouTube wall

YouTube's PO-token/SABR regime gates **stream delivery**: yt-dlp's own guide says
the token is now bound per video and per session, and Beatbump — a SvelteKit
YouTube Music frontend, the closest architectural neighbour — now requires an
`invidious-companion` sidecar purely to mint valid sessions. Hyperpipe is
discontinued. All of that is downstream of extracting audio.

`retrieve_player: false` skips the player entirely, and Timbre never extracts a
stream: playback is the IFrame player in the visitor's browser. **This is the
same structural line `BLOCKED.md` already draws about datacenter IPs, showing up
in a second place.** It is the strongest evidence yet that the "host nothing"
rule is load-bearing rather than merely principled.

**Honest caveats.** It is the same unofficial-private-API posture as
`ytmusicapi`, so it trades one maintenance burden for another — but for a much
more actively maintained project with a browser/Worker-capable build. Response
shapes are the library's own classes, so `normalize.py` would be rewritten, not
translated. And nothing here was run under Next's runtime; the numbers are plain
Node.

## F-3 · Mixcloud is a searchable, **queue-able**, keyless source — and it is the missing half of the catalogue

Not in the S-9 survey. It should be, because it is the only source found that is
simultaneously keyless to search, controllable by script, and strong on exactly
the two `SUGGESTED_SEARCHES` every other source fails.

**Search is keyless and browser-callable:**

```
GET api.mixcloud.com/search/?type=cloudcast&q=…&limit=…   200
  Origin: https://timbre.vercel.app
  → access-control-allow-origin: https://timbre.vercel.app
    access-control-allow-credentials: true
```

It reflects an arbitrary origin, so — like Audius, iTunes and the ListenBrainz
labs — it spends the visitor's IP rather than the shared egress one.

**Playback is a real player API, not a manual embed.** The Mixcloud Widget JS
API exposes `load(key, startPlaying)`, `play()`, `pause()`, `togglePlay()`,
`seek(s)`, `getPosition()`, `getDuration()`, `getIsPaused()`, and events
`progress` · `play` · `pause` · `ended` · `buffering` · `error`. That is
`playback: "api"` in `types.ts` terms — **a queue member, not a Spotify-style
panel** — and `ended` means the queue can advance itself.

### Measured against Timbre's own suggested searches

| Query | What came back |
|---|---|
| `boiler room set` | 5/5 genuine Boiler Room sets — Kaytranada (Montreal, 42 min), Apparat, Sampha, DJ Maseo (London), Altern 8 |
| `Fred again..` | the actual Boiler Room London set (71 min, 37k plays) and Glastonbury 2023 (65 min) |
| `lofi study mix` | real study mixes — *Chill study beats 3*, 93 min |
| `Aphex Twin` | Crack Magazine's *Best of Aphex Twin's SoundCloud dump*, The Vinyl Factory's *VF Mix 63 by µ-Ziq*, a 114-min Lefto show |
| `Wonderwall` | **weak** — DJ mixes *named* Wonderwall, not the song |
| `Sade` | Sade remix specials and soul shows, not *Smooth Operator* |

**This is the exact inverse of iTunes**, which `SUGGESTIONS.md` correctly ruled
out for returning "three unrelated songs *named* Boiler Room". Mixcloud is weak
on single tracks and strong on the long form — mixes, radio shows, DJ sets. Two
of six suggested searches go from "nothing good" to "five right answers".

Fields on a cloudcast: `audio_length`, `play_count`, `listener_count`,
`favorite_count`, `tags`, `user`, `created_time`, and `pictures` in ten sizes
including `320wx320h` and `640wx640h` — so the art proxy has real sizes to ask
for.

### Four things that will bite

- **Use `key`, never the display URL.** A search hit for the Kaytranada set
  carries `url: …/Amore-Music-Experience/…` but `key: /amemgmt/…`. The widget
  takes the `key`.
- **Durations are 40–130 minutes.** These are shows, not tracks. That is a
  product decision about what a queue entry is — the same decision
  `SUGGESTIONS.md` S-5 is about. A 71-minute Boiler Room set next to a 4-minute
  song breaks "no artist twice in three picks" in a way spacing was not designed
  for.
- **The embed licence is explicitly non-commercial and personal**, the widget
  must stay fully visible, and the Mixcloud logo must remain clickable through to
  mixcloud.com. That is the same shape as the visible YouTube iframe already
  shipped, so it costs nothing today — but it hard-binds the deployment to
  **E-1**'s open question about donations rather than leaving it open.
- **No exclusivity or geo flag in the public object.** Mixcloud Select shows and
  rights-restricted uploads exist and will fail at play time, exactly like a
  YouTube upload that refuses to embed. The fall-through ladder is the pattern;
  budget for it rather than assuming every hit plays.

**Where this goes:** a new provider, `searchable: true`, `playback: "api"`, and
an edit to `S-9` deleting the line that implies the survey is complete.

## F-4 · R1's missing index exists today, free, no key, no card

`SEARCH-ROUTES.md` R1 says the web-index route is "the strongest option for
both" and that **"the cost is the index"**, then lists Exa, Linkup, Firecrawl and
Serper as the surviving free tiers — every one of them an account.

**A public [4get](https://4get.ca) instance answers JSON with none of that.**

```
GET https://4get.nadeko.net/api/v1/web?s=<query>     200 · no ACAO · no key · no captcha
```

`4get.ca` itself requires a captcha-derived `pass` cookie (~100 requests/24 h);
`4get.nadeko.net` does not. No `ACAO`, so this is server-side only — unlike
almost everything else in this document.

Measured over 10 songs:

```
Spotify track id found      8/10
SoundCloud track URL found  9/10
```

**It reproduces `SEARCH-ROUTES.md`'s own R1 numbers exactly.** Wonderwall →
`1qPbGZqppFwLwcBC1JQ6Vr`; Fred again.. *Delilah* → `0Ftrkz2waaHcjKb4qYvLmz`;
plus `fredagain/delilah-pull-me-out-of-this`, `oasisofficial/wonderwall-2`,
`flume/never-be-like-you-feat-kai`, `peggygou/peggy-gou-it-goes-like-2`. Two
independent measurements, same ids.

**One trap, and it cost time here.** The `site:` operator returns **zero**
results on this instance's backend — `Oasis Wonderwall site:open.spotify.com`
→ `n=0`, while `Oasis Wonderwall spotify track` → four `open.spotify.com/track/`
URLs on the first page. Phrase the query, do not scope it.

The fragility is identical to soundcloak's and so is the containment: it is
somebody else's instance, and it belongs behind an optional env var of the same
shape as `SOUNDCLOUD_API_BASE`. 4get publishes an instance list, so unlike
soundcloak there is a fallback set.

**Note what this does to the ordering in Part 4.** R1 currently reads "measure
first with Serper's 2,500 free no-card queries, ship on Exa or Linkup". The
measurement is done, on neither. And for SoundCloud specifically, R1 at 9/10 is
now the *only* route that produces track URLs at all — F-1 returns 0/15 there.

## F-5 · A sixth recommendation list, from a population none of the other five sees

`RECOMMENDATIONS.md` names five lists and says the consensus multiplier is "the
term that makes the feature worth building". Every one of the five is a
*service's* opinion. There is a keyless list that is a *listener* opinion:

```
GET labs.api.listenbrainz.org/similar-recordings/json
      ?recording_mbids=<mbid>&algorithm=<enum>
  200 · Access-Control-Allow-Origin: *  ·  100 rows, 41 KB
```

Seeded on *Never Be Like You*:

```
359  The Chainsmokers feat. Daya — Don't Let Me Down
354  Kiiara — Gold
323  Sia — Cheap Thrills
312  Mike Posner — I Took a Pill in Ibiza (SeeB remix)
229  Disclosure feat. Eliza Doolittle — You & Me (Flume remix)
```

Each row carries `recording_mbid`, `recording_name`, `artist_credit_name`,
`release_name`, `caa_id` (Cover Art Archive) and `score`.
`/similar-artists/json` works the same way and also returns 100.

**Why it is worth more than a sixth list of the same kind.** It is
session-co-occurrence over ListenBrainz's own listening data — the same *kind* of
signal as YouTube's watch queue, computed by an organisation with no catalogue to
promote. When it agrees with YouTube Music and Deezer, that is three genuinely
independent populations agreeing, which is the strongest evidence the consensus
term can ever be handed. It also reaches the derivative layer on its own — that
Flume remix at 229 is the sort of thing `RECOMMENDATIONS.md` currently needs
`audius:versions` to find, from a source it correctly distrusts.

**It also answers point 4 of "Why not a trained model".** That section says "no
keyless source publishes genre, mood, tempo or embeddings… you would be training
on title strings." This is not item features, but it *is* a keyless
collaborative-filtering signal — the thing those features were wanted as a proxy
for.

**Two operational notes.** The `algorithm` parameter is a strict enum; send
anything and the `400` body lists every valid value, which is how the seven were
found. And it needs an MBID, so it rides the same Deezer-ISRC → MusicBrainz hop
as F-1 — build that once and both features land.

## F-6 · Cloudflare's free tier permits commercial use — which is `E-1`'s open question

`EXPOSURE.md` **E-1** is open on Vercel Hobby being non-commercial personal use
only, with donations counting as commercial; **E-3** is open on there being no
stable outbound IP; **E-4** is open on all three rate limiters being per-instance
and in memory.

Cloudflare's Workers free tier is documented as **permitting commercial use**,
needs no card, includes 100 000 requests/day, and includes **Workers KV** — a
shared counter for the limiters that is not a database in the sense
`WORKSTREAMS.md` rules out. Combined with F-2 this is coherent rather than a
platform swap for its own sake: `youtubei.js` is isomorphic and runs on Workers,
so **the sidecar's disappearance is what makes a single-Worker deployment
possible at all.**

**This entry is read, not measured, and is the only one here in that class.**
Nothing was deployed. Next 16 on `@opennextjs/cloudflare` was not tested, the
KV-backed limiter was not written, and the commercial-use claim comes from
Cloudflare's own pricing documentation rather than from counsel. It belongs in
`SUGGESTIONS.md`, not `BLOCKED.md`, until someone deploys a branch.

## F-7 · Smaller things, measured

- **`hearthis.at` is a keyless SoundCloud-shaped source.**
  `api-v2.hearthis.at/search/?t=…&count=…` answers `200` with
  `Access-Control-Allow-Origin: *`, full metadata and a `stream_url` per track.
  Catalogue is the same tier as Audius — *Fred again..* returns Glastonbury 2023
  and rooftop sets, `Aphex Twin` returns a Pukkelpop 2002 B2B with Luke Vibert.
  **It rate-limits hard from one IP** — `{"success":false,"message":"limit
  reached"}` after roughly four queries in a minute. Because it sends `ACAO: *`
  that limit is per *visitor* if the call is made from the browser and per
  *deployment* if it is made from a function. The same asymmetry `BLOCKED.md`
  records for Deezer, pointing the other way.

- **Background playback on Android is probably available, and the README
  overstates the block.** The README says background play is impossible for
  YouTube — true, it is inside the iframe — and that Audius "is technically
  different… but the behaviour is not built or tested". Android's Media Session
  integration with a plain `<audio>` element is documented as working fully: lock
  screen, notification tray, hardware keys. **iOS is the real exception** — audio
  stops when a home-screen PWA is minimised, and lock-screen control dies after
  ~30 s paused. So the honest sentence is per-platform, not per-source, and
  Audius on Android may already work by accident. Worth ten minutes with a phone.

- **`4get.ca` and `4get.nadeko.net` are not interchangeable.** `.ca` returns
  `401 {"status":"The \"pass\" token in your cookies is missing or has
  expired!!"}`. Do not benchmark the wrong one and conclude the route is closed.

- **Last.fm is the fallback for F-5, not the first choice.** `track.getSimilar`
  is free for non-commercial use, needs no per-call authentication, and supports
  CORS — but it needs an account and an API key, which ListenBrainz does not.
  Same signal, worse fit for the no-accounts posture. Recorded so it is not
  proposed as an upgrade.

- **Not reachable from this machine, so not measured:** Nina Protocol
  (`api.ninaprotocol.com`, DNS failure). Bandcamp answers `200` but exposes no
  public search API and no scriptable embed player — its iframe has no play API,
  so it could only ever be a Spotify-style manual panel. Neither is a gap.

## What is worth doing, in order

1. **Rewrite the cross-service entry in `BLOCKED.md`.** It currently asserts
   something false, and it is the entry the Spotify and SoundCloud entries both
   point at as root cause. (F-1)
2. **Build the ISRC → MBID hop once.** It is the shared prerequisite for the
   Spotify id (F-1) *and* the sixth recommendation list (F-5), and it is three
   keyless calls. Instrument the MusicBrainz miss rate — 2/15 here, and it is the
   weak hop.
3. **Prototype `youtubei.js` behind the existing sidecar interface.** The win is
   not the 6× — it is deleting a deployment target, a shared secret, two
   `EXPOSURE.md` entries and the single most common local failure mode. (F-2)
4. **Add Mixcloud.** Keyless, scriptable, and it fixes two of six suggested
   searches. Decide the long-form queue question first, because that is the real
   cost. (F-3)
5. **Point a sibling of `SOUNDCLOUD_API_BASE` at 4get** for the SoundCloud URLs
   F-1 cannot produce, same optional-env-var shape. (F-4)
6. **Leave Cloudflare alone until something forces it.** It is the right answer
   to three open `EXPOSURE.md` entries and the only unmeasured claim here. (F-6)
